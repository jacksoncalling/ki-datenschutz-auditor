## Unclear or contradictory instructions in the folder
1. **render.py cannot render the single-column report, and it fails silently.** rules.md, run-flow step 5, says to run `render/render.py jobs/<this>/report.md` and that both formats are accepted. render.py only parses platform table rows (`| [PS-n] ... |`). On a single-column report it exits 0 and writes a page saying "0 erfüllt · 0 Klärungen · 0 K.-o.", with 0 Prüfschritte. For a report that contains a CLEAR FAIL, that is actively misleading if forwarded. The only signal is a stderr warning about the title format. render/README.md does say it renders the platform report, so rules.md and render/README.md contradict each other. My call: I did not hand-build HTML, which rules.md forbids. I produced the platform rendering (perspectives.md: "a rendering, not a re-audit"), ran the checker on it as well, and rendered that.
2. **PS-0 for companies vs. the PASS rule.** checklist.md says that for an Unternehmen the DSB duty (`[BDSG-§38-1]`) should be named "in the Offene Entscheidung". rules.md says a PASS needs no Offene Entscheidung line. Here PS-0 is a PASS, so there is no slot. I put §38-1 in the PS-0 Bewertung and restated it under "Ergänzendes Recht", with that section's own Offene Entscheidung line.
3. **No place for the extra module in the output format.** checklist.md says to record the BDSG layer "as a short confirmation, not a sixth check". The rules.md template has no section for it; the name "Ergänzendes Recht" appears only in the other-Land case. I added `## Ergänzendes Recht (BDSG, Unternehmen)` between Befunde and Hinweis. Side effect: checks.py ends a finding block at the next `## `, so citations in that section are never validated. I checked them by hand. A phantom citation there would pass the gate unnoticed.
4. **The README describes files this drop-in does not contain.** These are listed or used but absent: `audit/keys/`, `audit/reports/`, `audit/fixtures/`, `audit/compliance-judge.md`, `audit/verify_bdsg.py`, `demo/`, `web/`. Only the layer-1 mechanical gates ran. I did not run `--all`.

## Judgment calls on classifications
- **PS-1 CLEAR FAIL** (most important). The Auto-Absage sends rejections automatically, is on by default, and the dossier says verbatim that no human review before sending is planned. "Sofern die Personalabteilung nicht vorher eingreift" is an opt-out, not a review, so at most a formal human role, which `[DSK-OH-1.6]` says is not enough. The DSK example is about auto-sent *invitations*; I applied it to rejections as the adverse variant. checklist.md itself names "auto-sends rejections" as the FAIL example. The feature looks configurable ("standardmäßig aktiviert"), which might suggest FLAG. I kept FAIL because the documented default behaviour is the contradiction, and an off switch is something to require, not to assume.
- **PS-2 CLEAR PASS (the most debatable call).** All eight Art. 28(3) lit. a-h elements, a closed sub-processor list with 30-day notice and objection, Germany-only processing and support, and no non-EU parent are stated explicitly. But the Satz 1 particulars (subject, duration, type of data, categories of data subjects) are not shown as AVV content, and Anlage 2 is summarised by function, not by company name. A strict reading of "silence is never a PASS" could make this a NARROW FLAG. I chose PASS because the checklist's three PASS criteria are each met with quotable evidence, and the Satz 1 facts are present elsewhere in the dossier (sections 1 and 4). I added a one-line note to check them against the original AVV. Also, LLM-operator parent-company access is not discussed separately, but "eine Übermittlung in Drittländer findet nicht statt" covers it as a blanket statement.
- **PS-3 NARROW FLAG, not FAIL.** Ziff. 8 ("Rückmeldungen ... können zur Verbesserung des Dienstes genutzt werden") could be read as the terms permitting training on the organisation's data, which would be a FAIL. I kept FLAG for three reasons. The dossier itself says it is unclear whether this means training. The conditional escalation needs an upstream model with no contractual training bar, and Ziff. 7 bars LLM training. And no applicant data has flowed yet, so the gap can be closed. The HR corrections relate to individual applicants and are therefore personal data, which is why this is a flag at all. The 12-month default history with no default-off is part of the same flag (`[DSK-OH-2.5]`, `[DSGVO-Art5-1e]`).
- **PS-0 CLEAR PASS.** The vendor states the DSFA duty explicitly and supplies a Muster-DSFA, data flows and a risk analysis. That matches "explicitly committed + vendor supplies system information". The company has not done its own DSFA yet. I treated that as the controller's next step, not as a dossier gap.
- **PS-4 NARROW FLAG.** Technical logic documentation exists; a plain-language explanation for applicants does not. That is exactly the checklist's FLAG case. Art. 13(2)(f) is directly engaged here because the Auto-Absage is an Art. 22 decision.
- **Missing documents.** The TOMs are referenced as Anlage 1 but their content is not in the dossier. I listed them under "Fehlend" rather than treating them as present.
